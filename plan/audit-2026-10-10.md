# Plan audit, 2026-10-10

A full review of the plan against the owner's direction of 2026-10-10: easy to start, a gentle
learning curve, an assistant path for everything, creation by description and interview, advanced
features kept and revealed over time. The principles and their mechanisms are in
[`19-assistant-first-experience.md`](19-assistant-first-experience.md) and ADR-017.

Method: every numbered plan document was read in full (01, 06, 09, 10, 11, 12 and the index by the
implementer; 02, 03, 04, 05, 07, 08, 13–18 by a delegated read-only audit whose findings were
spot-checked against the text before being acted on). Disposition codes: **Fixed** (the document
was changed in this revision), **Scheduled** (a roadmap or backlog item now carries it),
**Owner** (needs an owner decision; listed at the end), **Kept** (reviewed, deliberately unchanged).

## Overall findings

1. **The plan was correct about truth and silent about ease.** Canon integrity, review, history,
   isolation, and recovery are specified in depth. First-run, onboarding, plain language, and
   defaults were not specified at all; "onboarding, sample project, and recovery UX" was a single
   line in the last phase.
2. **AI was a drafter, extractor, and critic, never a collaborator.** No document specified an
   in-product assistant, an interview, or conversation. "Agentic planning assistants" sat under
   "later options". The only interview that existed (characters) was a port of the prototype.
3. **Every later phase added expert concepts with no default.** Branch, world time, narrative
   position, point of view, authority, visibility, tiers, profiles, suppressions, and rule ASTs
   were all author-visible inputs with no statement of what happens if the author ignores them.
4. **The plan was prose-first where the owner wants description-first.** Phase 2.5 and two other
   documents made pasting an existing manuscript the first workflow after canon.
5. **Story planning had models but no way to make a plan.** Phase 5 specified story, arc, beat,
   and scene-plan records and an editor; nothing described how an author gets from an idea to a
   plan.
6. **Several documents described finished work as future work**, or carried Phase 0 instructions.
7. **Work done on 2026-10-09/10 was outside the plan**: deployment, the interface redesign,
   assisted creation, and the to-fill-in list.
8. **Scope is large for one owner.** Audio and video, a local-inference connector, Google Docs
   and LaTeX intake, voice fingerprints, parallel review agents, and thirteen runbooks are all in
   release one. This revision does not cut them; it moves author-facing ease ahead of them and
   flags the heaviest for an owner decision. *(Decided 2026-10-21: audio, video and the Google
   Docs, LaTeX and DOCX paths are deferred past release one; see decision 4 below.)*

## Findings by document

### 01 Product and scope — Fixed
- Release-one workflow began "create and edit core world entities" by hand and reached AI only at
  "generate or paste a draft". Rewritten around the Describe → Interview → Draft → Review loop.
- "A questionnaire without the review-and-commit loop is a utility" is still true and kept; the
  converse is now also stated.
- No success measure covered learning. Added.
- "Agentic planning assistants" was deferred; an in-product assistant is now in scope.

### 02 Target architecture — Fixed (addendum), Scheduled
- Workflow list is form- and prose-shaped; there is no assistant module. Addendum adds the
  assistant as an application module and its workflows.
- "A model cannot introduce an unknown type without an explicit schema-extension decision" would
  block conversational creation. Clarified: the extension rides in the same proposal, and the
  author's approval is the explicit decision.
- Reads "resolve branch and timeline position" with no defaults. Defaults stated.
- The package-direction tree predated PostgreSQL canon. Marked historical.

### 03 Domain and temporal model — Fixed (addendum), Scheduled
- No defaults for the three clocks, branch scope, or alias scope. Defaults stated: one main
  branch, unspecified world time, author visibility, starter types.
- Plan records exist as a hierarchy with no creation path. Planning interview specified in
  document 19 and scheduled as Phase 2.6.
- Provenance origins had no "description or interview" source. Added as a required origin detail.
- Roughly forty-five core types before any need is shown. Kept in the model; the interface leads
  with five and the rest are one action away (built).

### 04 AI and retrieval — Fixed (addendum), Scheduled
- "AI participates in bounded, inspectable tasks" excluded conversation. Reframed: the assistant
  is a bounded task too; its tasks are listed.
- The scene pipeline starts with "validate the scene plan and required fields". Missing fields
  become questions, not failures.
- No evaluations for interview or plan quality. Added to the evaluation programme.
- "Entity resolution" is listed as evaluated; what is built is name and alias matching. Stated.

### 05 Storage and integrity — Fixed
- "Near-term Phase 2 corrections" was entirely done. Replaced with a pointer to the evidence.
- No storage for conversations, descriptions, or the to-fill-in list. Addendum specifies them.
- "Before Phase 3 retains Neo4j" is an unrecorded decision. Listed for the owner.

### 06 API and frontend — Fixed
- Information architecture was organised by data ("world workspace", "history workspace").
  Reorganised by level, with the assistant as the primary surface.
- "Add TypeScript before building product screens" and similar were done. Updated.
- No visual direction. Now `20-design-direction.md`.

### 07 Security and operations — Fixed (addendum), Scheduled
- The threat model omitted the in-product assistant: injection through pasted descriptions,
  transcript retention, runaway multi-call sessions. Added.
- Cost confirmation was per job; an interview is several calls. Session budget added.
- "Runbooks required before beta" while a deployment is live. Stated as a known gap.

### 08 Testing and quality — Fixed
- "Immediate test cleanup" was Phase 0 material. Removed.
- No invariant or release gate for the assistant, first-run, or plain language. Added.

### 09 Delivery roadmap — Fixed
- Phase 2.5 was prose-first; story planning was Phase 5; onboarding was Phase 7. Resequenced into
  2.5 (assistant-led creation), 2.6 (story planning by conversation), 2.7 (text intake).
- Every later phase now names its assistant path and level.

### 10 Backlog — Fixed
- No items for the assistant, onboarding, plain language, or grouped review. Added `AST-EXP-*`.

### 11 Decisions — Fixed
- "First complete workflow: plan scene → preview context → draft → review → commit" replaced.
- New open decisions added (below).

### 12 Current gap analysis — Fixed
- Did not record the deployment, redesign, or assisted creation. Added, with what is unverified.

### 13 Consistency system — Fixed (addendum), Scheduled
- Preflight "requires" plan fields; correction lists manual editing first; tiers, profiles,
  fingerprints, and suppression scope are author-visible. Addendum: one "Check" action with a
  plain cost, findings as margin notes, "explain" and "fix" by asking, tiers behind advanced.
- Proposals from descriptions and interviews were never checked against canon, only prose was.
  Scheduled in 2.5.

### 14 Distribution and hosting — Owner
- With an assistant-first product, "the portfolio instance never supplies a platform key" means a
  new author cannot use the main way in until they obtain an OpenRouter key. This is the largest
  remaining conflict with "easy to start". See owner decisions.
- No assisted first-run from invitation to first project. Scheduled in 2.5.

### 15 Prose editor and memory — Fixed (addendum)
- "The first manuscript intake path precedes generation" made prose the first workflow. Reframed
  as a second way in (Phase 2.7).
- Contradiction: intake "runs bounded extraction" yet works "without configuring a model
  generator". Clarified: marked entities resolve deterministically; extraction needs a model.

### 16 OpenCodeReview adaptation — Fixed
- Contradiction with 13 and ADR-013: model findings could become "blocking" after author
  confirmation. Corrected: only deterministic, current, complete evaluation blocks.
- Its read-only tool list is the natural toolset for the in-product assistant. Noted.

### 17 Multimodal context — Fixed (addendum), Owner
- Upload exposes authority, visibility, branch scope, and validity with no defaults. Defaults
  stated; "drop it in and the assistant asks what it is" specified.
- Audio and video in release one. Listed for the owner; deferred past release one by owner
  decision (2026-10-21).

### 18 Author rules, canon queries, derived views — Fixed
- "Before Phase 2 storage freezes" and "Phase 2 canonical query foundation" were done. Marked.
- "Thin text-first workflow immediately after Phase 2" superseded.
- Rules are authored as a typed predicate AST. Addendum: a rule is written as a sentence, the
  assistant drafts the AST with examples it would and would not catch, and the author reviews
  the examples; the AST is the advanced view.
- "Read-only MCP" allows proposal writes. Renamed "proposal-only".

## Correction, same day

The first version of this revision omitted the "God Hand" of the original `architecture.md`: a
general agent through which the author can change almost anything conversationally. The audit
compared the plan with the owner's stated principles but did not re-read the original concept
document, so the omission was not caught until the owner asked. It is now specified in document
19, scheduled in Phase 2.5, and tracked as AST-EXP-017. The legacy `GOD_HAND` traversal policy in
`backend/graph/policies.py` is a remnant of the prototype and is not that feature.
